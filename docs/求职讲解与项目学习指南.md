# 听荐：求职讲解与项目学习指南

## 简历项目描述

**听荐｜AI 无线耳机评论决策助手（个人概念项目）**  
**角色：产品策划 / AI MVP 落地｜时间：2026.09—至今**

- 回收并分析 56 份匿名需求问卷，其中 35 名为过去一年购买过或认真比较过无线耳机的核心用户；将“明确需求/比较产品”困难、信息过载与来源信任顾虑转化为 MVP 优先级，并明确便利抽样和样本结构限制。
- 设计“需求输入—AI 理解确认—证据检索—适配报告—原文核验—同需求商品比较”闭环，分开表达适配方向与证据强度，定义证据不足、观点冲突和模型异常时的“不确定”降级规则。
- 将概念原型实现为本地可运行 Demo：使用 FastAPI、`qwen-flash` 和 `qwen-plus` 完成需求解析与有引用报告生成；事实字段、正反统计和引用编号由程序控制，模型输出需通过后端追溯校验。
- 搭建 Amazon Reviews 2023 轻量范围抽样、清洗和六维证据派生流程；本地验证样本保留 106 条清洗后评论、生成 207 个证据单元，并通过后端、范围抽样和公开演示数据自动化测试。

> 简历中应写“本地可运行 Demo”和“探索性调研”，不要写成生产上线、市场代表性研究或真实业务转化。

## 一句话介绍

听荐不是直接替用户推荐耳机，而是先理解通勤、会议或运动需求，再从同一商品评论中找出可核对的正反证据；如果证据不足或互相冲突，系统会明确回答“不确定”。

## 三分钟面试结构

1. **问题**：总体星级和统一摘要不能回答“是否适合我的场景”。
2. **研究**：56 份问卷中，核心用户最常见的困难集中在明确需求、比较产品以及处理分散且过量的信息；来源不清和过度简化是主要信任顾虑。
3. **决策**：因此 P0 先做需求确认、维度化报告、正反证据和不确定状态；商品比较列为 P1；搜索、价格追踪和购买列为 P2。
4. **方案**：演示需求输入、理解确认、报告、证据详情和同需求比较五个关键步骤。
5. **AI 边界**：模型负责理解和表达，程序负责商品事实、统计和引用校验；无密钥或模型异常时回退到本地规则。
6. **验证**：需求问卷和技术链路已经完成；任务型真人测试尚未完成，因此不提前填写理解率或效率提升。
7. **反思**：问卷样本偏老且职业结构集中，真实评论样本也不代表市场；下一步先做 3–5 人任务测试和引用审计，再决定是否公开部署。

## 推荐学习顺序

1. 先看根目录 12 页作品集，建立“研究—洞察—决策—方案—验证”的故事线。
2. 打开 `原型设计/index.html`，完成一次“地铁通勤 + 视频会议”的选择任务。
3. 阅读 22 页 PRD，重点看产品范围、功能规则、证据机制、AI/程序分工和验收。
4. 查看 `research/README.md` 与分析工作簿，练习解释每个数字的实际分母和限制。
5. 查看 `docs/architecture.md` 和 `docs/evaluation-plan.md`，理解真实模型、数据和降级链路。
6. 按 `research/usability-test/` 的执行包完成第一轮真人任务测试，再把真实结果写回作品集。

## 高频追问

### 为什么需要 AI？

用户需求和评论都是非结构化文本，模型适合解析场景并把检索证据组织成自然语言；但商品、评分、数量和引用不能由模型自由生成。

### 为什么不用聊天框？

购买决策包含场景、关注维度和排除条件。结构化输入和确认页便于纠错，也保证两款商品使用同一组条件比较。

### 如何降低幻觉？

先限定商品和维度，再检索证据，最后生成；后端校验所有 `evidence_id`。引用失败、证据不足或模型超时时返回模板化结果，不强行推荐。

### 为什么不显示匹配百分比？

项目没有足够标注数据进行概率校准，百分比会制造虚假精确感，因此只使用“较匹配 / 不确定 / 较不匹配 / 无法判断”，并单独展示证据强度。

### 目前最大的不足是什么？

问卷是便利抽样，真人任务测试尚未完成，私有评论也只是两款匿名商品的小样本。当前可以证明产品逻辑和技术闭环可运行，不能证明真实市场采用或决策效率提升。
